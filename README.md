# Tic Tac Toe

ブラウザで遊ぶ三目並べです。実装は下のタスク順に、自分で進めます。

盤面のクリック、勝敗、履歴はすべてブラウザ上で扱います。型の練習もしやすいので、Vite + React + TypeScript で作ります。見た目は Tailwind CSS です。

## 仕様

- 2人で交互に、空いているマスへ X と O を置く。先手は X
- 勝ちが決まったら、そのプレイヤーを表示し、それ以上置けなくする
- 空きマスがなく、勝者もいなければ引き分けと表示する
- 各手番の盤面を履歴として残す
- 履歴から過去の盤面を表示できる
- 過去の局面から打ち直したときは、その手よりあとの履歴を捨てる

マスの位置は、左上を 0 として次のとおりです。

```
0 1 2
3 4 5
6 7 8
```

## 作業の進め方

上から順に進めます。各タスクの「できた」を満たしてから次へ進みます。

### 1. 開発環境を作る

できた: `npm run dev` で初期画面が開き、Tailwind CSS のクラスで文字の見た目が変わる。

ヒント:

- このフォルダには `README.md` がある。次のコマンドで、今のフォルダに React + TypeScript の Vite プロジェクトを作る。

  ```bash
  npm create vite@latest . -- --template react-ts
  ```

- 既存ファイルを残すか聞かれたら、残す方を選ぶ。`README.md` と `.gitattributes` を消さない。
- 依存関係を入れてから、Tailwind CSS と Vite 用プラグインを足す。

  ```bash
  npm install
  npm install tailwindcss @tailwindcss/vite
  ```

- `vite.config.ts` の `plugins` に、もともとある `react()` と、追加する `tailwindcss()` を並べる。
- `src/index.css` の中身を次の1行にする。`src/main.tsx` がこの CSS を import していることも確認する。

  ```css
  @import "tailwindcss";
  ```

- 確認用に、見出しへ `className="text-3xl font-bold"` を付ける。見た目が変われば Tailwind CSS は繋がっている。

### 2. マスと盤面の型を決める

できた: 空の盤面を `Board` 型の値として作れる。

ヒント:

- 1マスに入るのは X、O、空の3種類だけにする。

  ```ts
  type Player = "X" | "O";
  type SquareValue = Player | null;
  type Board = SquareValue[];
  ```

- `Board` の長さは 9。`Array(9).fill(null)` で空の盤を作る。
- `fill` の結果はそのままだと型が広がりやすい。変数には `Board` と注釈を付ける。

### 3. 9マスを表示する

できた: 空の 3×3 が画面に出る。この段階ではクリックできなくてよい。

ヒント:

- 盤面を `map` してボタンを 9 個出す。並びは固定なので、`key` はインデックスでよい。
- 3列にするには `grid grid-cols-3` が使える。
- マスの中身は、値があればその文字、`null` なら空文字にする。

### 4. クリックで X を置く

できた: 空のマスを押すと X が残り、同じマスを押しても上書きされない。

ヒント:

- 盤面は `useState<Board>` に入れる。
- 更新するときは、今の配列をコピーしてから、押した位置だけ変えた新しい配列を渡す。`board[i] = "X"` とその場で書き換えない。
- すでにマークがあるマスでは、何もせず戻る。

### 5. X と O を交互に置く

できた: 置くたびに次のマークが入れ替わり、画面に次の番が表示される。

ヒント:

- 手番を別の state に持ってもよい。あとで履歴を足すときは、「今見ている手数」の偶奇から計算する形にすると state が減る。先手が X なら、偶数手目は X、奇数手目は O。
- 勝者も引き分けも出ていないあいだは、`次の番: X` のように表示する。

### 6. 勝者を判定する

できた: 一列そろったら `勝者: X` のように出て、その後は置けない。盤が埋まって勝者もいなければ引き分けと出る。

ヒント:

- 勝ち筋は 8 本。横 3、縦 3、斜め 2。インデックスで書くと次のとおり。

  ```
  [0, 1, 2]  [3, 4, 5]  [6, 7, 8]
  [0, 3, 6]  [1, 4, 7]  [2, 5, 8]
  [0, 4, 8]  [2, 4, 6]
  ```

- 各ラインの 3 マスが同じ `Player` なら、その人が勝者。関数の戻り値は `Player | null`。
- クリック処理の最初で勝者を見る。すでに勝者がいるなら、盤面を更新しない。
- 勝者の表示中は「次の番」を出さない。

### 7. 履歴を保存する

できた: ゲーム開始時から現在まで、各時点の盤面が配列に順番で残っている。

ヒント:

- 履歴の型は `Board[]`。初期値は、空の盤が 1 つだけ入った配列。
- 手を打つたびに、その時点の盤面を末尾へ追加する。1手ごとに盤面を丸ごと持っておくと、過去へ戻るときに差分を計算しなくてよい。
- 画面に出している盤は、この段階では履歴の最後の要素にする。

### 8. 過去の盤面へ戻る

できた: 「ゲーム開始時へ戻る」「1手目へ戻る」のようなボタンで、その時点の盤面と手番が表示される。

ヒント:

- 今見ている手数を番号で持つ。表示する盤は `history[currentMove]`。
- 手番も、その番号の偶奇から決める。
- 履歴を `map` してボタンを並べる。0 件目だけ「ゲーム開始時へ戻る」にし、それ以外は「N手目へ戻る」にする。
- 例の画面では右側が `Go to game start` と `Go to move #1` の並び。文言は日本語でよい。

### 9. 戻った地点から打ち直す

できた: 3手目の盤面に戻して新しく置くと、それよりあとに残っていた古い履歴は消える。

ヒント:

- 置く直前の履歴を、今見ている手までで切る。`history.slice(0, currentMove + 1)` のうしろに、新しい盤面を足す。
- 足したあとは、見ている手数を新しい末尾へ進める。
- 最新の手から続けて打つ場合は、切っても中身は変わらない。同じ処理でよい。

### 10. 見た目を例に近づける

できた: 左に盤、右に番号付きの履歴が並ぶ。勝者や次の番は、その近くに読める。

ヒント:

- ゲームの動きが揃ってから見た目を整える。
- 外側は横並び。画面が狭いときは縦並びでよい。
- マスは同じ幅と高さ、枠線、文字は中央。
- 履歴は番号付きのリストにする。
